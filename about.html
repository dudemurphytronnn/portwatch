A neutral place to check the claim

"80% ported." "GPU instructions half mapped." Progress claims travel faster than commits. PortWatch puts each project's own words next to what its public repo shows, so you can judge the gap yourself.

What it covers

Open-source compatibility layers, emulators, recompilation and decompilation projects, driver layers and protocol bridges: the software that runs games and hardware features on platforms they were not made for. PS5 software on PC, Switch games on iPhone, SteamOS on Android, NVIDIA cards on macOS, CarPlay on Android head units, AirDrop on non-Apple devices.

It is for players following a port, journalists and creators covering one, and contributors choosing a project to join.

How the numbers work

  • Stars, forks, license, language, dates come from the official GitHub REST API. The catalogue is a dated snapshot; the date is shown at the top of the home page.
  • Stars per day is stars at the snapshot divided by days since the repo was created. It flatters young repos with a burst of attention, which is why every project page shows the commits too.
  • Last commit and last release are fetched live from GitHub when you open a project page. GitHub allows about 60 of these requests an hour per visitor; past that, the page falls back to the snapshot and says so.
  • Claims are quoted from the project's own description, README or release notes, each with the date it was read and a link to the source. PortWatch does not rate claims. It shows them beside the evidence.
  • Fork status (which repo is a registered fork of which, and how many commits ahead or behind) is asked of GitHub's compare API when you press "Check live" on the fork map or open a project page.

The listing rules

These keep PortWatch lawful, and every submitter affirms them.

  1. The repo is public on GitHub.
  2. It has an OSI-approved license or another clear license file. Repos with no license can be listed only when they are discussed widely enough to need a neutral record, and are marked "No license file".
  3. It bundles no game data, firmware, BIOS files, decryption keys or copyrighted assets, and does not link to places that host them.
  4. Game projects work only with a copy the user legitimately owns. Each listing carries a badge saying so.
  5. PortWatch links to repos and quotes metadata through the GitHub API. It hosts no code, binaries, firmware or game files, and never mirrors a repo.

The own-copy badge

  • Own copy required, stated by the project: the project itself says you need your own copy.
  • Own copy required (PortWatch rule): the project runs games or software you must supply. We apply the rule even when the repo does not spell it out.
  • No game files involved: drivers, bridges, installers and trackers.
  • Not a game project: repos kept only so they are not mistaken for something else, such as other projects called PortWatch.

Submissions and moderation

Anyone can submit a repo. The form checks in your browser, through GitHub's API, that the repo is public, what license it declares, and whether its file list contains anything that looks like game images or key files. The results go into a GitHub issue on the PortWatch repository, where a moderator reviews it in public. Nothing is listed without that review.

Fork notes

The plain-language notes on what each fork changes are community-edited. Suggest an edit from any family on the fork map; it opens an issue, a moderator merges it, and the note's revision history on the site records the date and what changed.

RSS and the weekly digest

The RSS feed lists every tracked project with its stars-per-day figure, and updates with each snapshot. The weekly email digest carries the same "fastest rising" list. Until the mailing list opens, any RSS-to-email service will deliver the feed to your inbox on a weekly schedule.

Takedown and DMCA contact

If you believe a listing links to infringing material, or that a listed project ships copyrighted assets or keys, open a takedown issue:

Send a takedown request

Say which listing, what the problem is, and your relationship to the rights involved. If your notice contains personal details you do not want public, open the issue with only the listing name and ask for a private channel; a maintainer will reply on the issue.

Listings named in a credible notice are hidden while they are reviewed. PortWatch hosts none of the code it lists, so removing a listing does not remove the repo. Notices about the repository itself belong with GitHub under its DMCA takedown policy.

Privacy

No accounts, cookies or analytics. Pages that show live numbers call api.github.com directly from your browser, so GitHub sees those requests. Answers are kept in your browser's session storage to save your rate limit, and cleared when you close the tab.
